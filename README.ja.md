# Ninja Ad (Stealth Switch)

*[English](README.md) | 日本語*

Chrome Manifest V3 の広告ブロック拡張機能。広告リクエストを強制ブロックすると
アンチアドブロック検知に引っかかるため、代わりにコンテンツタイプの合った空レス
ポンスへリダイレクトし、静かに HTTP 200 OK を返します。

## 仕組み

一般的な広告ブロッカーは `ERR_BLOCKED_BY_CLIENT` を返しますが、アンチアドブロッ
クスクリプトはこの読み込み失敗を捕まえて検知します。本拡張は、期待されるコンテ
ンツタイプに合致するローカルの noop ファイルへリダイレクトします。

| リソース種別 | 転送先 | 内容 |
|---|---|---|
| script, XHR/fetch, ping, object, other | `noop.js` | 妥当な空 JavaScript (`;`) |
| image | `noop.gif` | 1x1 透過 GIF (44 バイト) |
| sub_frame | `noop.html` | 最小の空 HTML 文書 |
| stylesheet | `noop.css` | 空の CSS ファイル |
| font, media, WebSocket | *(ブロックしない)* | 説得力のある応答を用意できない |

Chrome はレスポンスの `Content-Type` を noop ファイルの拡張子から決めるため、リ
ダイレクトが不可視でいられるのは**転送先が要求された種別に合っている場合だけ**で
す。HTTP 200 を返すだけでは足りません。`text/javascript` として配られたスタイル
シートは標準準拠モードで拒否され、画像はデコードに失敗し、フォントは
`document.fonts` の Promise を拒否し、動画は要素上で `error` を発火させます。こ
れはまさに本拡張が避けようとしているイベントです。

DNR のルールはアクションを 1 つしか持てないため、転送先をリクエスト時のリソース
種別によって切り替えることはできません。そこで種別を「正直に応答できる noop」ご
とにグループ化し、複数グループにまたがるフィルタは**グループごとに 1 本のルール**
として出力します。明記しておくべき帰結が 3 つあります。

- **font と media は一切ブロックしません。** リダイレクトしても検知され、ブロッ
  クしても同様に検知されるため、リクエストをそのまま通します。`$font` または
  `$media` のみを指定したフィルタは破棄され、`$media,script` は `script` に絞ら
  れます。
- **WebSocket もブロックしません。** *"Redirects are not supported for WebSocket
  requests"* — Chrome はリダイレクトを無視します。そもそも WebSocket は HTTP 101
  の Upgrade ハンドシェイクを必要とし、静的ファイルは 200 を返すので成立しませ
  ん。結果は「元のリクエストがそのまま通る」か「接続失敗で `WebSocket` の `error`
  が発火する」のいずれかで、後者は検知への対策どころか検知シグナルそのものです。
- **広告 CSS はフィルタが `$stylesheet` と明示している場合のみブロックします。**
  EasyList が `$stylesheet` を付けているのは約 58,000 本中 17 本で、`$type` オプ
  ションを持たない全フィルタに 1 本ずつルールを増やす価値がありません。明示され
  たフィルタは従来どおり `noop.css` へ転送され、汎用フィルタはこの種別を主張しま
  せん。

**一致しない種別は「無音の失敗」ではありません。** どのルールにも一致しないので
リクエストは通常どおり送出され、ページには拡張機能が入っていない場合とまったく同
じものが見えます。ブロックは減りますが、検知される材料はありません。

例外 (`@@`) ルールは、上記の狭い集合ではなく**ブロックされうる種別の全体**に対し
て解決されます。ブロックルールはグループごとに 1 本のコストがかかるため集合を絞っ
ていますが、例外は分割されないので広くしてもコストはゼロです。対抗するブロックよ
り狭い例外は、黙って例外として機能しなくなります。`@@||x/ad.css^` は
`||x/ad.css^$stylesheet` によるリダイレクトを止められません。priority 2 の
`allow` は、自分が主張していない種別を上書きできないからです。

ブロック処理はすべて Chrome ネイティブの C++ `declarativeNetRequest` エンジン内
で走ります。ネットワークリクエストごとに JavaScript が実行されることはありません。

YouTube では `youtube.js` がスキップボタンを自動クリックし、再生中の動画広告を末
尾まで進め、ページ内の広告枠を除去します。

すべてのコンポーネントが単一の ON/OFF スイッチに従いますが、その手段は 2 通りで
す。`youtube.js` は isolated world で動作し `chrome.storage` を直接監視します。
`spoofing.js` はページの MAIN world で動作し、そこには `chrome.*` API が存在しな
いため自分で状態を読めません。代わりに Service Worker が `chrome.scripting` 経由
で登録・登録解除します。したがって拡張機能を OFF にすると、次のページ読み込み以
降はページコンテキストへのパッチ適用も停止します。

### OFF を OFF のままに保つ

1 つのトグルが 4 つのもの（2 つのルールセット、注入スクリプト、バッジ）を駆動す
るため、`background.js` は保存値を単一の真実の源として扱い、3 通りに保護します。

- **更新の直列化。** `onStartup`、`onInstalled`、トグルメッセージはすべて 1 本の
  Promise キューを通ります。並行実行すると `await` が交互に進み、先に始まった同
  期処理が**最後に**終わってユーザーが切ったばかりの状態を再適用しかねません。
  キューによって「最後に要求された更新が最終状態になる」ことを保証します。
- **適用してから保存。** 新しい状態を先に適用し、成功した場合のみ保存するため、
  どのコンポーネントも従っていない値が保存されることはありません。
- **失敗時のロールバック。** 失敗した場合は保存値からすべてのコンポーネントを再導
  出し (`syncStateFromStorage`)、エラーを報告します。起きていない切り替えを成功と
  偽ることはしません。

**失敗許容は意図的に非対称です。** 有効化の途中で quota により extended ルール
セットを失うのは許容範囲で、失うのはブロック範囲だけです。一方**無効化の途中の失
敗は致命的**で、ロールバックします。無効化は quota を争わないため、そこでの失敗は
ルールがまだ生きていることを意味し、成功を報告すれば保存値 OFF に対して約 144,000
本のルールが動き続けることになります。

## インストール

**Chrome 102 以降**が必要で、manifest の `minimum_chrome_version` で固定していま
す。スイッチが `spoofing.js` に届くのは `RegisteredContentScript.world`
(Chrome 102+) のおかげで、DNR の `initiatorDomains` は Chrome 101+ を要します。こ
の固定がないと、古い Chrome は拡張機能を問題なくインストールしたうえで動的登録の
段階だけ失敗し、**ページコンテキストへのパッチを止められないスイッチ**が残ります。

1. Chrome で `chrome://extensions/` を開く。
2. **デベロッパーモード**を有効にする（右上のトグル）。
3. **パッケージ化されていない拡張機能を読み込む**をクリックし、**`src/` ディレク
   トリ**を選択する（プロジェクトルートではありません。ルートには配布してはなら
   ないビルド入力が置かれています）。
4. ツールバーに拡張機能アイコンが **ON** バッジ付きで現れる。

## フィルタルールの更新

フィルタの供給元は [EasyList](https://easylist.to/) です。更新手順:

1. [https://easylist.to/easylist/easylist.txt](https://easylist.to/easylist/easylist.txt)
   から最新の `easylist.txt` を取得する。
2. `filters/` に配置する。
3. コンバーターを実行する。生成された両ルールセットが `src/` に書き出されます。

```bash
node convert.js
npm test
```

4. `chrome://extensions/` で拡張機能を再読み込みする。

### コンバーターの動作

コンバーターは EasyList のフィルタ構文を解析し、Chrome DNR ルールを生成します。

- URL パターンと `$options` を `declarativeNetRequest` の条件へ変換する。
- `@@` 例外ルールを、より高い priority の `allow` アクションへ対応付ける。
- フィルタがまたがる noop グループごとに 1 本のルールを出力し、すべてのリクエスト
  が読み込める Content-Type で応答されるようにする。
- コスメティック (CSS 隠蔽) ルール、`$document`/`$popup` ルール、ホワイトリスト
  対象ドメインのルールをスキップする。
- DNR に相当機能のないオプションを持つルール（後述）と、提供可能なリソース種別が
  残らなかったフィルタをスキップする。

#### 未対応オプションは無視せず破棄する

黙って無視されたオプションは「弱いルール」を生むのではなく、**別のルール**を生み
ます。`$generichide` はコスメティックフィルタのみを制御するため、これを無視すると
`@@||example.com^$generichide` が全リソース種別に対するネットワーク `allow` にな
り、そのドメイン全体のブロックを解除してしまいます。`$csp` と `$rewrite` も同様
に、全リソース種別を覆うリダイレクトへと劣化します。

そのためコンバーターは、認識できないオプションをその行に対する致命的エラーとして
扱い、ビルドサマリで `unsupported=` として件数を報告します。ルールを破棄すれば失
うのは少しの範囲ですが、黙って誤変換すれば保護そのものが無効になります。

## 設定

### ホワイトリストドメイン

以下のドメインはビルド時にブロック対象から除外されます (`convert.js` 内)。

- `google.com`, `google.co.jp`
- `gstatic.com`, `googleapis.com`
- `youtube.com`, `ggpht.com`
- `accounts.google.com`
- `gemini.google.com`, `bard.google.com`

このリストは 2 つの機構で使われますが、**保証を担うのは一方だけです**。

- **実行時のガードルール** — core ルールセットの先頭に置かれた、最高 priority
  (`3`) の `allow` ルール 1 本で、`requestDomains` で一致します。フィルタの書き方
  に関係なく要求先ホストで一致するため、実際にこれらのホストを保護しているのはこ
  ちらです。
- **ビルド時の走査**（最適化のみ） — ホワイトリストドメインを明記したフィルタを
  破棄し、ガードが常に上書きするだけのルールを生成しないようにします。一致判定は
  ホスト境界を考慮します。単純な部分文字列判定では、無関係な広告ホスト
  `gggpht.com`（実在する EasyList のエントリ）を飲み込み、`google.com.evil.net`
  を Google と誤読するためです。

**走査だけでは不十分**であり、それがガードの存在理由です。`/pagead/conversion.js`
のような汎用フィルタは Google に一言も触れていませんが、
`https://www.google.com/pagead/conversion.js` に一致します。なお `requestDomains`
は*要求先*ホストを制約します。`initiatorDomains` は呼び出し元ページを制約する別の
条件で、ここでは何も保護しません。

ホワイトリストを変更するには、`convert.js` の `WHITELIST_DOMAINS` 配列を編集して
コンバーターを再実行してください。

### ルールの priority

| priority | ルール種別 | アクション |
|---|---|---|
| 1 | ブロックルール | noop ファイルへリダイレクト |
| 2 | 例外 (`@@`) ルール | allow（ブロックを回避） |
| 3 | ホワイトリストガード（1 本） | allow（すべてを回避） |

### 2 つのルールセットと Chrome の静的ルール枠

Chrome が保証する静的ルールは拡張機能あたり **30,000 本**のみです。EasyList は現
在約 174,000 本のルール（約 58,000 フィルタ、その多くが noop グループごとに 1 本
ずつ出力される）を生み、超過分は他のインストール済み拡張機能と共有するプールから
確保されます。

決定的に重要なのは、`updateEnabledRulesets()` が**アトミック**であることです。あ
るルールセットの有効化によって共有プールの余力を超える場合、呼び出しは拒否され、
**変更は一切行われません**。Chrome は収まる分だけ読み込んで残りを捨てる、というこ
とはしません。したがって 174,000 本の単一ルールセットは全か無かになり、quota
チェックに一度失敗すれば拡張機能は何もブロックしなくなります。

コンバーターは出力をこれに合わせて分割します。

| ルールセット | ルール | 有効化 | 失敗時の影響 |
|---|---|---|---|
| `rules-core.json` | 30,000 本: ガードルール、**すべての**例外ルール、続いてフィルタごとの `noop.js` ルール | manifest では `false`。`background.js` が保存状態から有効化 | 保証枠に収まるため quota で拒否されない |
| `rules-extended.json` | 残り (約 144,000 本) | `false`。`background.js` がベストエフォートで有効化 | ブロック範囲の縮小。警告としてログ出力 |

**ルールはフィルタ単位ではなく noop グループ単位で出力されます。** どちらの順序で
も生成されるルールは同一で、動くのは core/extended の境界だけです。フィルタ単位の
順序では、保証された 30,000 本が先頭約 7,500 フィルタの全バリアントに費やされま
す。グループ単位なら約 29,400 フィルタの `noop.js` バリアントに費やされ、image・
sub_frame・stylesheet のバリアントは extended ルールセットに回ります。これはどち
らの方向でもより良い失敗の仕方です。広告のスクリプトをブロックすればその画像リク
エスト自体が発生しないことが多く、また extended を有効化できない場合、種別固有の
ルールは単に一致しないので、それらのリクエストは誤った Content-Type で応答される
のではなくそのまま通ります。

**すべての例外 (`allow`) ルールは core ルールセットに入ります。** 破棄されうる側
に取り残された例外は、core のブロックルールを上書きするものが無い状態で発火させ、
これがサイトを壊す原因になります。例外だけで保証枠を超えた場合、`convert.js` はビ
ルドを失敗させます。この分割は `test/static-rules.test.js` で検証されています。

ルールの一致と priority は有効なすべてのルールセットを横断して適用されるため、
core ルールセットの priority 2 の `allow` は extended ルールセットの priority 1 の
`redirect` を上書きします。

### manifest からはどちらのルールセットも有効化しない

`rule_resources` の両エントリは `"enabled": false` を宣言し、`background.js` が保
存された ON/OFF 状態から有効化します。これは様式ではなく**必須**です。Chrome は有
効なルールセットの集合をセッション間では保持しますが、**拡張機能の更新をまたいで
は保持しません** — *"the `rule_resources` manifest key will determine the set of
enabled static rulesets on each extension update."* manifest で有効と記されたルー
ルセットは、ユーザーの選択に関係なく更新ごとに復活し、Service Worker が無効化する
までブロックを続けます。

**OFF から始めることで失敗の向きが反転します。** 更新はワーカーが走るまでの一瞬
「ブロック不足」になりうるだけで、保存値 OFF の裏でブロックすることはありません。
フェイルオープンのコストは広告数個ですが、フェイルクローズは OFF 保証を破ります。
それは本拡張の存在意義そのものです。

### リソース種別の安全性

`main_frame`（文書）と `popup` はすべてのルールから除外されています。これにより拡
張機能がブラウザタブを強制的に遷移させることを防ぎます。`font`、`media`、
`websocket` は上述の別の理由で除外されています。本拡張が生成できるどのレスポンス
も、本物と見間違われることがないためです。

## ファイル構成

`src/` が配布される拡張機能そのものです。その外側はすべてビルド入力またはテスト
であり、`src/` 以外が Chrome に読み込まれることはありません。

```
ninja-ad-plus/
├── src/                        # ← 読み込み対象: パッケージ化された拡張機能
│   ├── manifest.json           # MV3 設定（権限、ルールセット、Service Worker）
│   ├── background.js           # Service Worker: ルールセット/spoofing のトグル、バッジ、storage 同期
│   ├── spoofing.js             # MAIN world の広告/アンチアドブロックスタブ（background.js が登録）
│   ├── youtube.js              # YouTube 動画広告スキップとページ内広告除去
│   ├── popup.html              # ポップアップ UI: 状態表示付きトグルスイッチ
│   ├── popup.js                # ポップアップ制御: 状態の読み書き、トグルメッセージ送信
│   ├── rules-core.json         # 生成物: 全例外を含む 3 万本、保存状態から有効化
│   ├── rules-extended.json     # 生成物: 超過分、ベストエフォートで有効化
│   ├── noop.js                 # 空 JS (script, XHR, ping, object, other)
│   ├── noop.gif                # 1x1 透過 GIF（画像広告）
│   ├── noop.css                # 空 CSS（明示的な $stylesheet フィルタのみ）
│   ├── noop.html               # 空 HTML（sub_frame の広告枠）
│   ├── icon48.png              # ツールバーアイコン
│   └── icon128.png             # 拡張機能管理ページ用アイコン
├── filters/                    # ビルド入力。配布されない
│   ├── easylist.txt            # EasyList フィルタ供給元
│   └── antiadblockfilters.txt  # アンチアドブロックフィルタ供給元
├── test/                       # node --test のテストスイート
├── convert.js                  # ビルド手順: filters/*.txt -> src/rules-{core,extended}.json
├── icon-source.png             # フル解像度のアイコン原画（icon48/128 はここから生成）
├── package.json                # `npm test`
├── .gitignore
├── README.md
└── README.ja.md
```

原画を編集したらアイコンを再生成します。

```bash
sips -s format png -z 128 128 icon-source.png --out src/icon128.png
sips -s format png -z 48  48  icon-source.png --out src/icon48.png
```

`test/static-rules.test.js` は参照されていないファイルが `src/` に現れると失敗す
るため、ビルド入力が気づかれないまま配布ディレクトリへ紛れ込むことはありません。

## セキュリティ上の考慮

- **リモートコード実行なし**: すべてのルールは事前コンパイルされ同梱されます。実
  行時のネットワーク取得はありません。
- **ページコンテキストのスプーフィングは切り替え可能**: `spoofing.js` は一般的な
  広告/アンチアドブロックのグローバル変数をスタブ化するため、ページの MAIN world
  に `document_start` で注入されます。ローカルに同梱され、リモートコードを読み込ま
  ず、拡張機能を OFF にすると完全に登録解除されます。したがって、これが壊してしま
  うサイトは OFF にして再読み込みすれば必ず復旧できます。
- **bait 保護は名前の厳密一致**: `spoofing.js` は寸法プロービングを無効化するた
  め、クラスや id が広告の bait に見える非表示要素を強制表示します。各クラストーク
  ンは bait 語と完全一致するか、bait 語の直後が `-`/`_` である必要があるため、
  `address`、`admin-dialog`、`adaptive-layout` は対象外です。開放的な前方一致にす
  ると、あらゆるサイトで通常の非表示 UI が `!important` で強制表示されてしまいます。
- **main_frame のリダイレクトなし**: 強制遷移を防ぐため、文書レベルのルールは明示
  的に除外しています。
- **最小限の権限**: 下記の 4 権限のみです。`scripting` は MAIN world スクリプトの
  キルスイッチのために取得しており、リモートコードや任意コードの注入には使いませ
  ん。登録するスクリプトは同梱の `spoofing.js` だけです。
- **ドメインホワイトリスト**: 重要サービス（Google、YouTube）をビルド段階で誤ブ
  ロックから保護しています。
- **web_accessible_resources**: noop ファイルは全 URL に公開されます（リダイレク
  トに必要）。これらのファイルには実行可能なロジックも機密データも含まれません。

## 権限

| 権限 | 目的 |
|---|---|
